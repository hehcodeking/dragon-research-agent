# 龙头短周期研究模型与验证边界

本项目把“市场情绪、题材共振、强势股辨识、仓位管理”转成可解释的研究规则，使用 10 万元模拟初始资金、8% 最大回撤停机阈值。它不保证盈利，也不声称掌握或复刻陈小群、92 科比、紫阳东路等交易者的私人策略。示例得分是规则分数，不是胜率、收益预测或荐股结论。

8% 是触发停止新增风险的阈值，不是账户损失上限。跳空、跌停无法卖出、T+1 以及价格缺失均可能使实际回撤超过阈值。首版只做研究、日线回放和本地模拟交易，券商接口留作扩展。

## 1. 可检验的假设

研究假设是：在短线参与度较高、跌停压力有限时，同一催化方向中的流动性较好、连板辨识度较高的股票，可能具有次日关注价值。假设必须接受样本外验证，退潮期主动减少交易也是模型输出。

首版不尝试用日线数据证明“打板成交”“弱转强盘中承接”“排板回封”“分时低吸”或真实交易者席位跟踪。上述行为需要对应时点的逐笔、盘口、分钟行情、交易回报及其他证据，不能由日线 OHLC 还原。

## 2. 输入能力和缺口

依据用户提供的 Financial-API 文档，适配器可读取涨停、跌停、炸板池及报价。完整市场池用于市场状态，限定数量的个股报价只用于候选丰富，不能把截断后的候选数冒充全市场涨停数。

| 输入 | 可用于首版 | 不应作出的推断 |
| --- | --- | --- |
| 涨跌停、炸板池 | 连板、封单、涨停池时间、市场数量 | 池时间不保证是首次或最终封板时间；封单不代表一定成交；历史查询不证明当时已经公开 |
| 行情快照 | 最新价、成交额、OHLC 等公开字段 | 批次 `timestamp` 是最新上游有效时间，不证明每个标的都刚更新 |
| 涨停原因 | 文本相同的题材代理分组 | 它不是稳定的行业分类；缺失原因不能被聚为一个强势题材 |
| `is_st` | 明确为 true 时排除；缺失时拒绝入场 | 缺失不能默认 false |
| `is_new` | 未开板新股风险标记 | false 不证明已经超过上市前五个交易日，也不证明正常涨跌幅限制适用 |
| 历史日 K | 明确 `adjust=none` 的假设成交和估值 | 默认前复权价格不能直接用于真实现金、涨跌停及委托价格计算 |
| 龙虎榜 | 在实际公布并被记录后用于复盘；首版不参与交易信号 | 不可把营业部、服务商游资标签或聚合净买额等同于某人的实际账户、持仓或下一步动作 |
| 集合竞价 | 可单独采集阶段和状态，供未来版本研究 | 接口组装时间不代表上游行情时间；9:25 终态不能回填到 9:20 决策 |
| 高频动向文档 | 说明能力边界 | 文档中的 `1m` 高频动向序列不是分钟价格 K 线；文档同时注明该模块当前不可外部调用 |

公开历史行情接口只约定日线；本地文档不能证明线上权限、延迟、稳定性或历史覆盖。真实请求验证前，不应宣称已接通实时行情。接口不提供券商委托执行。

## 3. 已实现的透明规则

运行版本为 `leader-rules-v1`，权重和阈值在 `dragon_agent/strategy.py` 和 `dragon_agent/config.py` 中公开。以下是启发式研究规则，不存在从公开资料中推导出的“稳定盈利参数”。

设 U 为涨停数，D 为跌停数，F 为炸板数，H 为最高连板高度：

```text
炸板率 B = F / (U + F)，分母为 0 时不应推定为强势
封单保留率 P_i = seal_money_i / max_seal_money_i
```

这些比值需要分母有效、单位一致、时间口径一致。封单是时点存量，成交额是期间流量；封单不解释为订单成交概率或资金真实净流入。P 大于 1 视为数据矛盾并排除，不无限加分。

状态按下表从上至下判断；总仓预算同时受配置 `max_exposure` 约束。

| 状态 | 判断条件 | 默认总仓预算 |
| --- | --- | --- |
| 数据不足 | U、D、F、H 任一缺失、非有限数或非非负整数 | 0 |
| 退潮 | D ≥ 15 或 B ≥ 45% | 0 |
| 低温 | U < 15 | 0 |
| 活跃 | U ≥ 60、D ≤ 5、H ≥ 4、B ≤ 25% | 60% |
| 修复观察 | U ≥ 25、D ≤ 8、B ≤ 30% | 35% |
| 分歧 | 其余有效输入 | 15% |

完整池数量缺失、分页不完整、时间不一致时关闭新入场。“修复观察”只是截面标签；跨日状态转移模型需要额外的连续历史快照，不能仅凭一张快照认定完整的情绪周期。

候选按下列分数降序、股票代码升序稳定排序。默认最低合格分为 65 分。

```text
得分 = 30 × min(连板计数 / 4, 1)
     + 20 × min(相同涨停原因标签股票数 / 4, 1)
     + 20 × 当前封单额 / 峰值封单额
     + 15 × min(成交额 / (最低成交额 × 4), 1)
     + 15 × clamp((900 - 涨停池时刻分钟数) / 300, 0, 1)

涨停池时刻分钟数 = 小时 × 60 + 分钟
默认最低成交额 = 3 亿元
```

输出保留各特征分量、原值、解释和排除原因。连板计数小于 2 或大于默认上限 6 直接排除；非主板、ST / 新股状态非明确 false、停牌、缺有效价格、缺题材、封单异常、成交额不足或涨停时间无效也排除。日线快照中的字段名 `first_limit_time` 沿用初版命名，其真实接口来源是 `limit_up_time`，名称不能证明它是首次涨停或最终封板时间。服务商的连板计数和“5 天 4 板”标签不能自动当成连续涨停天数。

数据完整且通过研究筛选对应 `eligible=true`，满足逐股行情时戳、可信停牌状态、前收盘及明确涨跌停价等额外门禁才有 `execution_ready=true`。前者的目标权重是条件性研究预算，不是下单许可。行情补全数量有限时报告必须说明候选覆盖限制。

默认最多选 3 只、单票 20%、总仓 60%、同涨停原因标签 35%；按排序依次分配剩余预算。其中 35% 仅约束这一批研究计划，模拟券商当前不跟踪已有持仓的题材属性，不能把它当成跨日组合题材风控。实际模拟券商另核查已有持仓、现金、费用、单股及总仓上限和风险阈值。这些是控制集中度的初始实验参数，并非最优值证明。建议先用固定参数验证，再做小范围敏感性分析，不在全历史上反复搜索最佳参数后宣称有效。

## 4. 时间证据和无未来数据约束

每个快照至少记录交易日、数据时点 `asof`、首次可供模型使用的 `available_at`、捕获时间、来源和覆盖状态。`available_at` 不能早于 `asof`。历史重放只能在信息实际可用之后决策。

今天调用历史池得到昨日数据，不能把今天的捕获时间改成昨日收盘后。只有独立保存的当时快照或可信的公布时点证据，才支持 point-in-time（PIT）回放。龙虎榜文档的零点时间戳只是目标日期标签，不能据此在当天开盘前使用收盘后榜单。

当前报价不能与过去交易日的涨停池拼成一个“历史实时”信号。`historical=True` 只允许关闭相对于当前墙上时钟的过期检查，不允许绕过未来数据、排序、结构或可用时间验证。缺失的字段必须保留为 null，并给出阻断原因。

同日终态的最高价、最低价、封单峰值、最终涨停原因、收盘封单和全日成交额，在当天开盘时均未知。日线回放允许这些数据用于收盘后信号，成交必须发生在后续已提供交易日的开盘；不能用同日开盘价成交。

## 5. 日线回放能证明什么

日线回放的目的首先是验证因果顺序、资金记账和风险规则，而不是模拟排板成交。

- 仅普通主板、长仓、现金账户；不模拟融资、融券、杠杆、科创板、创业板或北交所权限。
- 只使用下一已提供交易日的开盘价并计入滑点和费用。日线开盘撮合是实验假设，不是交易所保证。
- 只在具备明确涨跌停价、价格、停牌状态及可信时间证据时考虑成交。涨停开盘买入、跌停开盘卖出采取保守的不成交处理；没有盘口队列不能宣称排队成交。首版不按当日全日成交量限制开盘成交量，因为全日量在开盘时未知；它也没有开盘集合竞价成交量和冲击成本模型，因此容量与成交数量可能过于乐观。
- 买入后遵守 T+1；触发止损可能必须等后续交易日，不能保证在止损价卖出。日线最高 / 最低价不能被用来同时择优安排止盈和止损顺序。
- 买入按 100 股整数倍；卖出不足 100 股的尾数按支持范围一次处理。假设成交价必须遵守最小价格单位和价格范围。
- 仓位估值使用持仓对应行情；标的未出现在次日候选池中并不代表它已卖出、停牌或价格为零。沿用旧估值必须明确标记并阻止新风险，不能默默美化净值。
- 普通现金卖出所得可参与后续买入的假设、佣金最低收费、印花税、过户费和滑点口径需要随报告保存。具体费率应按用户券商与交易日更新。
- 跨除权除息、拆分、合并、退市和长期停牌的数据需要独立处理。首版没有完整公司行动账本，含此类事件的区间不具备完整绩效解释能力。

报告应保留逐笔原因、拒单原因、未成交数量、交易费用、现金、持仓估值、净值路径和最大回撤。最后一个数据日的持仓不得假装在不可成交的收盘价格清仓。

## 6. 接入实盘前还需要的证据

券商扩展应由结构化指令连接风控后再到执行接口，LLM 文本和新闻内容不直接获得下单权。扩展须提供账户 / 持仓 / 委托 / 成交查询、幂等订单号、撤单、部分成交状态、错误回报、重连与对账；券商成交回报才是现金和持仓变化的依据。

首版的禁用实盘适配器不能靠把一个布尔配置切为 true 就下单。选择具体券商后，需要其正式接口、账户权限、程序化交易报告确认、测试环境与连接参数才能开发并验证真正的路由。不得用行情 API Key 充当券商交易凭据。

按时间拆分训练、验证、测试，固定参数做滚动样本外验证；至少覆盖不同市场状态，报告交易笔数、胜率、平均盈亏比、收益分布、回撤、空仓时间、容量与成交拒绝率。特别增加手续费提高、滑点扩大、连续跌停、T+1 止损延迟、数据中断、重放重复订单等压力场景。合成示例只证明软件能运行，不证明策略有超额收益。

## 7. 规则核验记录（2026-10-03）

采用交易所正式文件而非旧教程。以下是实现边界的摘要，相关安排以后可能调整。

1. 沪深《交易规则（2026 年修订）》均自 2026-07-06 起施行。普通主板仍有 10% 涨跌幅、买入整手及特殊无涨跌幅日等规则；主板风险警示股票已由 5% 改为 10%，不能把旧 ST 5% 常量用于当前股票。首版排除风险警示和新股，并要求输入明确涨跌停价格。参见 [上交所正式规则及附件](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[上交所修订说明](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml) 和 [深交所正式规则 PDF](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。
2. 深交所正式规则第 3.1.4、3.3.8、3.3.11—3.3.15 条分别涉及交收前卖出限制、整手数量、最小价格单位及价格限制和例外。需要按证券和交易日判定，不能仅凭代码或昨收乘固定比例完全确定。盘后固定价格交易适用范围已扩大；首版日线开盘模型没有实现盘后交易。[规则原文](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)
3. 程序化交易实施细则从 2025-07-07 起施行，会员客户首次程序化交易前须向券商报告并经核查确认。是否频繁交易不能替代报告义务判断；本地研究、生成计划与真正下单接口应清楚区分。参见 [上交所细则](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml) 和 [深交所细则 PDF](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020250403603802169453.pdf)。
4. 龙虎榜公开信息披露的是符合条件股票的相关营业部或交易单元及其买卖金额，不能据此验证特定自然人的账户行为。[深交所公开信息披露规则说明](https://www.szse.cn/www/investor/knowledge/stock/deal/t20230406_599703.html)

本文件中的模型和风控建议是工程设计判断；交易规则事实来自以上官方来源。接口字段判断来自用户提供的本地契约，尚不构成线上认证或服务能力验收。
